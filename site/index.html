AI can generate explanations. LYR tells you whether they actually refer to the world.

Not "what's most likely" — what is currently identified, what is only a measurement artifact, and what a single next observation would resolve.

A real incident, two ways ↓
● Real case — from this project's own deployment history (Case 001)
A GitHub Action failed. The log shows: configure-pages: Get Pages site failed

Traditional AI

"The Pages deployment failed."

It restates the error message as the diagnosis — treating the measurement's output as if it were the cause.

LYR

World hypotheses
Pages not enabledworkflow misconfigtoken permstransient outage
Measurement assumption
The message "Get Pages site failed" is generic across all four causes — so it is a measurement artifact, not evidence for any one of them.
Identified — on the log alone
Nothing. All four hypotheses remain live. The error text identifies no cause.
Identified — after a witness
Pages was never enabled. Witnessed by the settings state + a single-line fix (enablement: true) that made the next run succeed.
Still unidentified
Whether token permissions would have blocked a later step; whether any transient contributed.
Next observation
A run with Pages enabled but permissions removed would close the first; GitHub status history closes the second.

Every claim above is tagged with the assumption it rests on. The diagnosis is stated with what it still doesn't know — that is the whole point.
