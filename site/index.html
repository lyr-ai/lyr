The proof · what's real today

How does LYR become harder to fool?

An ordinary system goes error → diagnosis. LYR goes error → knowledge → diagnosis: it separates what happened from how it was measured, and states the diagnosis with what it still doesn't know. This real incident is knowledge doing the work for the first time.

● Real case — from this project's own deployment history (Case 001)
A GitHub Action failed. The log shows: configure-pages: Get Pages site failed

Surface reading

"The Pages deployment failed."

This repeats the observed failure but does not identify its cause — it treats the measurement's output as if it were the world.

LYR

World hypotheses
Pages not enabledworkflow misconfigtoken permstransient outage
Measurement assumption
The message "Get Pages site failed" does not discriminate among the four candidate causes — so it is treated as a measurement artifact, not evidence for any one of them.
Identified — on the log alone
Nothing. All four hypotheses remain live. The error text excludes none of them.
Identified — after a witness
Pages was never enabled. Witnessed by the settings state + a single-line fix (enablement: true) that made the next run succeed.
Identified under
the settings state is reliable; no other relevant change occurred; the successful rerun was not explained by a transient recovery.
Still unidentified
Whether token permissions would have blocked a later step; whether any transient contributed.
Next observation
A run with Pages enabled but permissions removed would close the first; GitHub status history closes the second.

Every claim above is tagged with the assumption it rests on. The diagnosis is stated with what it still doesn't know — that is the whole point.
